02 / The problem

规模扩大后，
两道瓶颈同时出现。

抽样决定能否看见全局结构；共识计算决定算法能否真正跑在大数据上。

01 / REPRESENTATIVENESS

代表点覆盖不足

纯随机采样可能遗漏规模较小或形状复杂的簇，基础聚类结果随采样波动。

02 / COMPUTATION

全局共识代价高

稠密相似矩阵和反复迭代会增加存储、节点间交换与同步成本。

研究目标：在聚类质量、结果稳定性与分布式效率之间取得平衡。

03 / Architecture

先做好每一次聚类，
再让结果形成共识。

框架分为 SRC 基聚类与 SREC 集成共识两层。

04 / Base clustering · SRC

少量代表点，
保留尽可能多的结构。

RSP 与 K-means 结合选择代表点；FAISS 连接数据点与近邻代表点，形成稀疏二部图。

01

覆盖全局

通过 RSP 子集上的 K-means 寻找代表点，降低单次随机采样遗漏局部结构的风险。

02

保持稀疏

借助 FAISS 近邻检索构图，避免直接处理所有样本对之间的稠密关系。

03

形成基础划分

SRC 在图结构上完成聚类，为后续集成提供质量更稳定的基础结果。

05 / Ensemble · SREC

让多个基础划分
汇成一个最终答案。

SREC 将 SRC 生成的多个划分进行加权谱共识，并用 Tcut 在稀疏图上得到最终簇划分。

06 / Distributed execution

让算法的结构，
适合并行执行。

论文基于 Spark 实现 SREC：RSP 将数据组织为可处理的子集，多个基础聚类任务在集群中展开，再汇入稀疏共识阶段。

01 / PartitionRSP 数据划分
把大规模数据组织成多个样本子集
02 / ParallelSpark 并行计算
SRCSRCSRC
并行生成多组基础聚类划分
03 / ConsensusSREC 稀疏共识
整合基础结果并输出最终簇

下方步骤概括分区、并行和共识；计算节点数量与任务调度位置不按实验部署复刻。

10 / Takeaway

从代表点到共识，
把大规模聚类串成一条可执行的链路。

SREC 通过更有代表性的采样、稀疏图与非迭代共识，兼顾聚类质量、稳定性和分布式计算效率。
