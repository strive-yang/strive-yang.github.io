02POSITION

Not a scaffold

它不是文件脚手架，
而是治理决策引擎。

传统 bootstrap 从“可以生成什么”出发；这个 Skill 从“当前究竟缺什么”出发。

−

Template-first

先生成，再让项目适应模板

README、AGENTS、specs、plans、decisions……文件齐全，不代表边界清晰。

+

Evidence-first

先证明问题，再增加治理

能复用就不修订，能跳过就不创建；“什么都不改”也是合法且有价值的结论。

Governance ladder

从零开始，只在证据要求时升级。

每一次升级都必须说清：低一级为什么解决不了当前的协作、交付或风险问题。

  1. 0NONE

    无需新增治理

    默认行为或既有约定已经足够，输出 No additional governance required。

  2. 1LIGHT

    轻量契约

    用一个持久化说明解决边界问题，通常最多增加 1–2 个简洁产物。

  3. 2STRUCTURED

    结构化协作

    持续协作确实需要独立的规范角色、计划或作用域策略。

  4. 3GOVERNED

    正式治理

    仅用于审计、合规、严格追踪、高风险审批或明确的多团队边界。

Governance budget

每个候选产物只能选择 create / reuse / revise / skip / ask，且每个非 skip 动作都必须解决一个已被识别的问题。

How it works

一次完整判断，七个可验证阶段。

先把“现状是什么”与“目标需要什么”彻底分开，再决定是否写入。

  1. 01

    Discover

    扫描代码、配置、测试、文档与既有 Agent 指令。

  2. 02

    Classify

    独立判断成熟度、当前治理状态与交付模式。

  3. 03

    Resolve roles

    为规范权威、实现证据和描述文档划清边界。

  4. 04

    Select level

    从 Level 0 开始，停在第一个足够的等级。

  5. 05

    Write gate

    按风险决定直接写入、确认或暂停。

  6. 06

    Write minimally

    只修改必要的最小语义表面，并保持幂等。

  7. 07

    Validate

    检查权威唯一性、链接、安全、平台假设与二次运行结果。

Repository knowledge model

三类知识，不能混作一个事实来源。

verified designed unknown
A

Normative authorities

回答“应该是什么？”——策略、需求、计划、架构决策与作用域规范。

B

Implementation evidence

回答“实际是什么？”——代码、配置、测试、Manifest 与安全的运行检查。

C

Descriptive documentation

回答“如何向人解释？”——README、运维文档、Onboarding 与参考页面。

Put it to work

把它应用到你的仓库。

该 Skill 默认只接受显式调用。选择最接近当前场景的提示词，复制后交给 Agent。

01NEW REPOSITORY

新项目接入 Agent

判断当前成熟度，并只建立真正必要的起步契约。

Use $bootstrap-project-contract to inspect this new repository and establish the minimum Agent governance it actually needs.
02EXISTING REPOSITORY

已有项目重新评估

识别事实来源、冲突与漂移，仅补齐缺失的契约片段。

Use $bootstrap-project-contract to reassess this repository's current governance, identify the source-of-truth files, and add only the missing Agent contract pieces.
03OVER-GOVERNED

检查是否治理过度

推荐最低充分目标，但不未经确认删除或迁移现有权威。

Use $bootstrap-project-contract to determine whether this repository is over-governed. Recommend the lowest sufficient target contract and do not delete or migrate existing authorities without confirmation.

Installation

保留完整目录，放入 Skill 搜索路径。

核心模型保持平台无关。只有仓库已采用某个平台约定，或你明确选择平台时，才加载相应适配规则。

Codex repository-local 示例 .codex/skills/bootstrap-project-contract/

不同 Agent 平台的 Skill 搜索路径可能不同，应以实际平台配置为准。
