01 / The idea

收藏只是起点。
理解，才值得留下。

读到一篇好文章之后，真正需要留下的是：它解决了什么问题，证据是什么，以及下次什么时候能用上。

01

围绕问题组织内容

先找出文章的核心问题，再展开背景、方法和实践建议。论文、工程案例与产品评测，各有合适的表达结构。

02

让结论带着来源

按需核对论文与代码等一手材料，区分实际核验、公众号转述和整理者建议，让数字与条件出现在一起。

03

让归档形成闭环

文章进入已核验的飞书总索引，写入后回读正文、来源和目录关系；已有文章先读取，再修订原件。

02 / From link to library

一条链接，五步沉淀。

由现有 Agent 执行，官方飞书 MCP 连接知识库。
展开每一步，查看输入、动作与检查。

INPUT / 公众号原文OUTPUT / 个人知识库
01核读原文Read the source先确认，读到的是完整文章+

读取标题、来源、正文与图片地址，识别验证页和内容缺失。遇到访问限制时明确说明，保留需要补充的资料。

检查点：原文完整性与可访问性
02核对证据Check the evidence关键结论，可以追溯到哪里+

按文章需要核对论文、代码与官方资料，标明已核验内容和原文转述。重要数字同时说明实验条件与来源；无法核对的部分保留不确定性。

检查点：来源、条件与证据层级
03整理资料卡Make it understandable围绕核心问题，讲清方法与边界+

围绕一个核心问题组织背景、方法、证据、适用边界与实践建议，形成适合技术分享的汇报式资料卡。章节由内容决定，篇幅随解释需要展开。

检查点：能否讲明白，以及何时能用
04归档到飞书Archive with context总索引 → 文章子页面+

核验用户指定的总索引与编辑权限，通过官方飞书 MCP 写入或修订文章子页面，并维护索引链接。已有文章先读后修订，按来源链接复用原件。

检查点：目标位置、权限与已有记录
05回读与记录Verify and remember写入之后，再确认一次+

回读正文、来源、父子目录关系和总索引。本地 article-status.json 记录处理阶段、结果与地址，帮助后续修订和同链接复用；文章正文与原图归档在飞书。

检查点：最终内容、目录关系与处理状态

流程定义集中在 feishu-wechat-knowledge / SKILL.md ↗

03 / A note you can reuse

留下的，
是能再次使用的理解。

知识资料卡的价值，在于把一篇文章变成可以讲给别人、也能带回实践的解释。

  • 易懂交代必要背景，把术语放回问题与方法中解释。
  • 可汇报保留清晰的叙事主线，为技术分享提供材料。
  • 可迁移说明适用条件、实践建议，以及哪些结论仍需核验。

正文、原图、分类与总索引归档在飞书；本地状态文件只保留来源、阶段、结果和地址。

04 / Start your library

带上两条链接，
开始你的知识积累。

准备好自己的飞书总索引和公众号原文链接，再让 Agent 按 Skill 开始工作。

  1. 01
    准备本地环境

    Windows、Node.js 20+、Python 3.10+，以及支持 Skill 和 MCP stdio 的 Agent；下载仓库后安装锁定依赖。

  2. 02
    接入自己的飞书

    填写本地应用配置，按文档开通权限与完成 OAuth，配置项目级 MCP 连接，核验目标总索引的编辑权限。

  3. 03
    提交文章与归档入口

    复制提示词，填入自己的两条链接。后续继续复用已核验的入口与文章状态。

阅读完整 Windows 接入说明 ↗
