为什么记录从研究理解方法从文章理解取舍从工具走向使用从哪里开始

你好，我是 Yang Strive。这里集中展示我的研究、技术笔记与开源作品，也保留它们从问题走向实现的过程。

做研究时，一个结果需要方法和实验支撑；做工具时，一个功能需要放到真实的使用场景里检验。我希望把这两种习惯留在同一个地方：既说明“做了什么”，也尽可能交代“为什么这样做”和“适合怎样使用”。

这篇文章是站点的开篇。随着公开内容增加，下面的导览也一并更新，方便第一次来访的读者找到感兴趣的方向。

从研究，理解方法

研究部分围绕机器学习与大规模数据聚类展开。目前可以阅读 SREC 大规模集成聚类研究图解：从代表点采样、稀疏图构建，到加权共识与分布式实验，把论文中的方法链拆成便于阅读的图解。

图解提供快速建立整体认识的入口，算法流程、实验图表和论文原文则提供进一步核对的依据。希望读者既能看见方法解决的问题，也能理解实验结论所依赖的条件。

从文章，理解取舍

技术名词背后，真正值得讨论的是场景与代价。从传统 RAG 到 Agentic RAG 用一个 iOS 用户流失排查的示意案例，串起混合检索、质量校验、关系与层级索引，再走向多来源调查。

文章关注的问题是：什么失败需要什么能力，增加一个步骤会引入多少成本，以及答案能否回到原始证据。案例中的业务情境用于解释方法，方法的来源可以继续在文末参考资料中查阅。

从工具，走向使用

项目与工具部分收录可以直接查看、试用或阅读源码的作品。目前有在 Windows 任务栏显示 Codex 剩余额度的 QuotaRail，也有把技术文章整理成飞书知识资料卡的 feishu-worker，以及帮助仓库建立合适协作约定的 bootstrap-project-contract。

如果只是想立即体验一个小功能，可以打开 阶梯提成计算器 或 EPUB 手机阅读器。每个入口都尽量说明用途与使用方式；开源项目也保留代码和反馈渠道，便于继续了解实现。

从哪里开始

  • 想快速了解我的工作：先看 项目 和 研究，从具体成果进入细节。
  • 想读一个完整的技术案例：从 RAG 文章 开始，沿着问题、方法和选型依据阅读。
  • 想查找最近的变化：访问 归档，查看文章与站点更新的时间线。

如果你对某个方法、项目或实现有兴趣，可以通过 GitHub 或 邮件 找到我。感谢你的阅读。
